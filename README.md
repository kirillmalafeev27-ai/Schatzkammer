# Сокровищница · Die Schatzkammer

Игра для тренировки немецкого. Каждый верный ответ — шаг искателя сокровищ по залу. Золото тяжелеет, дверь опускается с первой секунды: успел выйти — добыча твоя, не успел — ноль.

Phaser 4 + TypeScript, весь арт рисуется кодом в стиле комикса, свет — собственный шейдер. Вопросы задаёт обучающий движок Conveyor с форматами заданий из Druckmaschine: 49 лексических и 60 грамматических тем от A1 до B2, девять форматов заданий, режимы узнавания, свободного воспроизведения и аудирования, генерация пакетов на сервере и встроенный резерв.

## Запуск

```bash
npm install
cp .env.example .env.local   # задайте AITUNNEL_API_KEY — без него игра идёт на встроенном резерве
npm run dev                  # http://localhost:5173, API движка подключено к тому же серверу
```

Рабочий режим — один Node-процесс отдаёт и игру, и API:

```bash
npm run build      # проверка типов, затем всё нужное для запуска — в dist/standalone/
npm start          # игра и API на 0.0.0.0, порты 8080 и 3000 (свой номер — PORT или PORTS)
```

Ключи читаются из окружения, `.env.local` и `.env` и в браузер не попадают. Все переменные — в [`.env.example`](.env.example). Выкладка на Northflank — ниже, в разделе [Northflank](#northflank).

Параметры адреса:

| Параметр    | Что делает                                                                 |
| ----------- | -------------------------------------------------------------------------- |
| `?level=3`  | сразу открыть зал 3 (`7` — бесконечный зал)                                |
| `?debug`    | панель отладки (в режиме разработки она открывается клавишей <kbd>`</kbd>) |
| `?art=grey` | серый прототип вместо комиксного арта                                      |
| `?test`     | выключить автопереключение качества по FPS (для автотестов)                |

Управление: нажать на плиту — цель шага; <kbd>1</kbd>–<kbd>4</kbd> — ответ; <kbd>Enter</kbd> — отправить свободный ответ; стрелки — шаг в сторону; <kbd>H</kbd> — к выходу; <kbd>Пробел</kbd> — отменить цель; <kbd>Q</kbd> / <kbd>E</kbd> — выбросить монету / камень; <kbd>P</kbd> или <kbd>Esc</kbd> — пауза (из поля ответа — только <kbd>Esc</kbd>).

## Обучающий движок

Задания генерирует тот же модуль, что в «Шахте» и See Escape, — [`quiz-generation.cjs`](quiz-generation.cjs), копия байт в байт: правила по грамматическим темам (`TOPIC_RULES`), требования к качеству и формат «AUFGABEN / LOESUNGEN» с проверкой ключа. Пул на клиенте работает по правилам «Шахты». Меню, режимы и панель — из Conveyor; встроенный резерв написан в девяти форматах Druckmaschine. Подробности — в [docs/GENERATION.md](docs/GENERATION.md).

**Меню.** «Играть» открывает выбор зала, а над залами — блок «Немецкий», как стартовое окно Conveyor: уровень (A1–B2), режим, лексика (49 тем в шести группах) и грамматика (60 тем в восьми группах, последняя — «Лексика» с Wortfelder). Рядом — состояние пула: «AI-пул активен», если генерация настроена на сервере, и «умный резерв активен», если нет. Выбор сохраняется (`treasury:learning`).

**Режимы.**

- Узнавание — четыре варианта, клавиши <kbd>1</kbd>–<kbd>4</kbd>.
- Воспроизведение — ответ вводится текстом. Сначала строгое сравнение (регистр, пунктуация и пары ä/ae, ö/oe, ü/ue не ошибки), затем, если не совпало, смысловая проверка моделью на сервере: равнозначная формулировка принимается, другой смысл — нет.
- Аудирование — немецкая фраза только звучит (ElevenLabs при ключе, иначе голос браузера), варианты — русские переводы, «▶ Повторить» проигрывает её снова. Своя очередь `audio | уровень | лексика`: к грамматике не привязано.

**Задания.** Генератор пишет задание с пропуском `___` (или двумя), сборку предложения из частей через `/` и выбор правильного предложения; у тем из `TOPIC_TASK_MIX` — ещё преобразование (`… → Perfekt`) и исправление ошибки (`… (1 Fehler)`). Perfekt идёт смесью пяти типов: Partizip II, Hilfsverb и Partizip вместе, преобразование, исправление ошибки, сборка предложения; чистый выбор haben/sein — не больше одного задания на пакет. Инструкцию над заданием игра ставит по-русски по виду задания (`generatedFormatOf` в `src/learning/client.ts`). Перевода и разбора генератор не пишет — их показывают только задания резерва. Аудирование — немецкая фраза и четыре русских перевода; после ответа фраза показывается в строке разбора.

**Панель вопроса** показывает инструкцию формата, уровень и тему, задание, перевод, поле слова, подсказку и строку разбора. Разбор ответа остаётся под следующим вопросом приглушённым, пока игрок не ответит снова. На телефоне панель ужимается сама: сначала шрифт и отступы, на 360 × 640 — инструкция и банк слова в строку, а разбор всплывает поверх задания на время ответа. Варианты-предложения в портрете идут столбиком, а если четыре ряда не помещаются — снова по два в ряд, с переводом в одну строку.

**Пул** ([`src/learning/pool.ts`](src/learning/pool.ts)) — правила «Шахты» (`QuizBankProvider`, перенос `QuestionBank` из See Escape):

- к модели не обращаются, пока игрок не пошёл играть: пул пополняется на экране выбора зала и в залах, в главном меню запросов нет;
- пакет из 10 заданий запрашивается, когда в очереди меньше 3; последние 12 формулировок уходят серверу в `exclude`;
- смена темы или уровня: запрос уходит, когда выбор устоялся (0,7 с), а не на каждый щелчок; пакет, пришедший после смены темы, ложится в очередь своей темы;
- после неудачи новый запрос не раньше чем через 15 с, каждая неудача подряд — вдвое дольше, до двух минут; первый успех сбрасывает паузу; ответ без новых заданий — тоже неудача;
- невыданный остаток и показанный, но не отвеченный вопрос хранятся в `localStorage` сутки (`schatzkammer.quiz.pool.v1`): после перезагрузки они отдаются без нового запроса;
- своя очередь на `уровень | лексика | грамматика`, узнавание и воспроизведение делят одну; вопрос с ошибкой возвращается в хвост, но не показывается два раза подряд;
- пока очереди нет, без ожидания берётся встроенный разноуровневый резерв — сначала задания своей темы; вопрос выбирается в момент показа, так что первые вопросы раунда уже из пакета.

**Сервер** ([`server/`](server)) — маршруты генератора «Шахты» и своя проверка свободного ответа:

| Маршрут                              | Что делает                                                               |
| ------------------------------------ | ------------------------------------------------------------------------ |
| `GET /api/quiz/status`               | готовность генерации и озвучки, провайдер и модели — без ключей          |
| `POST /api/generate-questions`       | пакет грамматических заданий (AITunnel или любой OpenAI-совместимый API) |
| `POST /api/generate-audio-questions` | пакет заданий на аудирование                                             |
| `POST /api/tts`                      | mp3 по немецкой фразе (ElevenLabs), кэш в памяти и на диске              |
| `POST /api/questions/evaluate`       | проверка свободного ответа: строгое сравнение, затем смысловое моделью   |
| `GET /healthz`                       | проверка живости                                                         |

Первые пять отдаёт `quiz-generation.cjs` через переходник [`server/quiz-routes.ts`](server/quiz-routes.ts): модуль написан под express-подобное приложение, а сервер «Сокровищницы» — на стандартных Request/Response. Модели из `AI_MODELS` (по умолчанию `gpt-5.4`) пробуются по очереди, у каждой свой таймаут `AI_TIMEOUT_MS`. Остаток пакета сверх запроса лежит в пуле сервера на комбинацию `уровень | грамматика | лексика` и отдаётся следующему запросу без модели. Частота генерации ограничена: 6 пакетов в минуту на клиента и 30 в целом. Если сервер сообщил, что генерация не настроена, клиент не шлёт запросов и играет резервом.

### Расход на генерацию

Вызов модели стоит столько же, сколько в «Шахте»: запрос около 2 500 знаков, ответ — 10 коротких заданий в тексте «AUFGABEN / LOESUNGEN». Прежний запрос по системе Druckmaschine весил около 16 000 знаков (каталог девяти форматов с примерами, свод правил темы, правило субстанции, самопроверка), а модель писала в ответ 14 заданий в JSON с переводом и разбором и иногда платила за вторую попытку — один вызов выходил почти в пять раз дороже. Тест [`tests/quiz-generation.test.ts`](tests/quiz-generation.test.ts) держит запрос короче 4 000 знаков.

## Northflank

Деплой устроен так же, как в Conveyor: те же скрипты, тот же `Dockerfile`, тот же выбор портов.

### Пошагово

1. Код должен лежать на GitHub (в Windows это делает `push-to-github.cmd` — двойной щелчок, он отправит проект в ветку `main`).
2. В Northflank: **Create new → Service → Combined service**.
3. Репозиторий — `kirillmalafeev27-ai/Schatzkammer`, ветка — та, где лежит этот код.
4. **Build**: тип сборки `Dockerfile`, путь `/Dockerfile`, контекст `/`.
5. **Networking / Ports**: добавьте порт `8080`, протокол HTTP, публичный доступ включён. Номер `3000` тоже сработает.
6. **Environment**: секрет `AITUNNEL_API_KEY` (без него игра работает на встроенном резерве). Для озвучки аудирования — `ELEVENLABS_API_KEY` (необязательно, без него читает голос браузера). Остальные необязательные переменные — в [`.env.example`](.env.example).
7. **Health checks**: readiness и liveness — HTTP `GET /healthz` на том же порту.
8. **Resources**: одна реплика — пул остатков живёт в памяти.
9. Run command оставьте пустым. Создайте сервис, дождитесь сборки и откройте публичный адрес. В логах при старте должна быть строка `[northflank] PORT= PORTS= -> binding 8080, 3000 on 0.0.0.0`.

### Что внутри

- `Dockerfile` собирает игру командой `npm run build:node` и кладёт в образ только `dist/standalone/` — сервер (`server.js`, без `node_modules`), игру (`public/`) и запускающий скрипт `northflank-serve.mjs`; работает от пользователя `node`, `.env`-файлов в образе нет.
- Northflank **не** подставляет `$PORT`, поэтому без `PORT`/`PORTS` контейнер слушает сразу `8080` и `3000`, и любой из этих номеров в port entry доходит до игры. Для другого номера задайте `PORT` (или `PORTS` через запятую) в переменных сервиса.
- run command можно не задавать (`node northflank-serve.mjs` из `CMD`); `npm start` и `npm run start:northflank` ведут туда же.

Если сервис собирается из репозитория, а не из `Dockerfile` (buildpack/Git-сборка):

- build command: `npm ci --no-audit --no-fund && npm run build:node`;
- run command: `npm run start:northflank` — или оставьте пустым: `npm start` ведёт в тот же скрипт.

`npm run start:northflank` подставляет `NODE_ENV=production` и `HOST=0.0.0.0`, разбирает `PORT`/`PORTS`, пишет в лог итоговый список портов и сам собирает `dist/standalone`, если сборка прошла без `build:node`.

### Ingress отвечает `Connection refused`

`upstream connect error ... Connection refused` приходит от прокси Northflank, а не от игры: контейнер поднялся, но на порту, куда постучался прокси, никто не слушает. По порядку:

1. Сервис собирается из ветки, где есть корневой `Dockerfile` и `scripts/start-northflank.mjs`? Без них buildpack запустит старый `npm start`, и до ingress он не дойдёт.
2. Номер в port entry совпадает с тем, что в логе старта: `[northflank] PORT=... PORTS=... -> binding ... on 0.0.0.0`.
3. Если номер нестандартный — задайте `PORT` или `PORTS` в переменных сервиса и передеплойте.

## Встраивание

Без `questions` игра берёт встроенный обучающий движок (как на автономной странице). Свой источник подключается так:

```ts
import { mountTreasury, type QuestionProvider } from './src/embed';

const questions: QuestionProvider = {
  async next() {
    return {
      id: 'q1',
      prompt: 'Ich ___ müde.',
      promptLang: 'de',
      options: ['bin', 'bist', 'ist'],
      optionsLang: 'de',
      correctIndex: 0,
    };
  },
  report({ id, correct, timeMs }) {
    // ответ игрока — для статистики или интервальных повторений
  },
};

const game = mountTreasury(document.getElementById('host')!, {
  questions,
  level: 1, // необязательно
  storage: { get: (k) => localStorage.getItem(k), set: (k, v) => localStorage.setItem(k, v) }, // необязательно
  onFinish: ({ level, escaped, score, stars }) => {}, // необязательно
});

game.destroy();
```

Игра не знает, откуда берутся вопросы: годится любой источник с `next()` и `report()`. Необязательные поля вопроса включают форматы движка: `instruction`, `meta`, `translation`, `rule`, `audioText`, `wordField`, `hint` и `recall` (свободный ответ, проверка — `evaluate()` источника). Простой пример источника — `LocalBankProvider` с банком `src/questions/bank.de.json` (60 проверенных вопросов).

## Устройство

```
src/core/       правила: чистый детерминированный TypeScript без Phaser — редуктор, генератор залов, планировщик, оценка риска
src/config/     все числа (balance.ts, levels.ts) и все цвета (palette.ts)
src/art/        процедурный комикс: обводка, растр, штриховка; рецепты пола, стен, героя, добычи, двери
src/render/     свет ComicLight, виды героя, предметов, двери, песка, эффекты
src/scenes/     BootScene (запекание атласов) и GameScene
src/ui/         DOM-интерфейс: панель вопроса, мешок, экраны меню, залов, итогов, настроек
src/audio/      синтезатор на WebAudio: эффекты, пещерная реверберация, эмбиент
src/questions/  интерфейс вопросов и локальный банк
src/learning/   обучающий движок: темы, каталог форматов, резерв, пул, проверка ответа, озвучка
server/         API движка: генерация, проверка ответа, озвучка; Vite-плагин и рабочий сервер
server/exercises/  свод правил по темам, требования к качеству, сборка запроса, проверка ответа модели
docs/           GENERATION.md — как устроены задания
scripts/        сборка и запуск для Northflank: build-node, start-northflank, northflank-serve
tools/          sim.ts (симуляция ботами), shots.ts (скриншоты)
```

Отклонения от плана, их причины и отчёт симуляции баланса — в [DECISIONS.md](DECISIONS.md).
